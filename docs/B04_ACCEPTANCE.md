# Приемка B04: инфраструктурная основа

Статус: проектная часть подготовлена; техническая активация и аварийные тесты
выполняются до пилота

## 1. Подготовлено в репозитории

- правила веток, commit, pull request, review, версий и миграций;
- шаблон pull request и CODEOWNERS;
- минимальный CI без внешних зависимостей проекта;
- описание local, test/CI, staging и production;
- политика секретов и персональных доступов;
- перечень метрик, логов и критических тревог;
- политика резервных копий и протокол восстановления;
- runbook выпуска, отката и инцидента;
- безопасный план сведения локальной и удаленной истории.

## 2. Принятые решения

| Решение | Значение |
|---|---|
| Git-процесс | ветка → pull request → CI → review → squash merge |
| Основная ветка | защищенная `main`, без прямых и force push |
| Production | Timeweb Cloud, два app-узла и три PostgreSQL-узла |
| Владелец аккаунта | владелец фабрики |
| Данные вне production | тестовые или обезличенные |
| Подтвержденные операции | целевой RPO 0 в принятой модели отказов |
| Восстановление | целевой RTO до 4 часов |
| Копии | WAL + ежедневные + еженедельные + отдельный контур |
| Плановый merge | squash |
| Срочные тревоги | Telegram как основной кандидат, звонок как резерв |

## 3. Что проверяется сейчас

- `bash scripts/check-repository.sh` проходит локально;
- CI-файл валиден и запускает ту же команду;
- локальные ссылки и JavaScript прототипа проверяются;
- запрещенные файлы не отслеживаются Git;
- документация согласована между собой.

## 4. Что нельзя честно принять без инфраструктуры

- фактический failover PostgreSQL без потери подтвержденной операции;
- развертывание одного образа на staging и production;
- восстановление полной копии за четыре часа;
- доставка тревог реальным ответственным;
- правила защиты `main` и работа CI в приватном GitHub-репозитории.

Эти проверки являются обязательными воротами перед пилотом, а не причиной
покупать ресурсы на этапе документации.

## 5. Определение «готово»

B04 полностью готов, когда:

1. GitHub baseline сведен без потери истории и данных;
2. `main` защищена, CI обязателен и успешно проходит;
3. staging развернут автоматически из версионированного образа;
4. секреты разделены по окружениям;
5. выполнены тест отказа app-узла и БД;
6. выполнено и запротоколировано полное восстановление;
7. критические тревоги доставлены основному и резервному ответственному;
8. владелец подписал протокол инфраструктурной приемки.
