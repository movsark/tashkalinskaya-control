# B17. Приёмочные сценарии

## Автоматизированное ядро

- **A17-01:** одно outbox-событие создаёт одну запись на получателя.
- **A17-02:** повторный цикл worker не создаёт дубль.
- **A17-03:** неизвестное событие не поглощается обработчиком B17 и не создаёт push.
- **A17-04:** получатель определяется только среди активных сотрудников и ролей.
- **A17-05:** прямой получатель из payload не получает дубль от своей роли.
- **A17-06:** обычное сообщение в тихие часы остаётся в ленте, а push переносится на 07:00.
- **A17-07:** важная и критичная тревога доставляется без ожидания тихих часов.
- **A17-08:** временная ошибка push создаёт новую попытку с задержкой.
- **A17-09:** ответ 404/410 отзывает подписку и завершает доставку.
- **A17-10:** успешный push не ставит `read_at`.
- **A17-11:** открыть и отметить прочитанным можно только собственную запись.
- **A17-12:** первая отметка прочтения идемпотентна.
- **A17-13:** непрочитанная важная тревога получает один повтор через 15 минут.
- **A17-14:** критичная тревога получает второй уровень через 30 минут.
- **A17-15:** прочитанное сообщение больше не эскалируется.
- **A17-16:** отключение push отзывает только подписку, но не удаляет ленту.
- **A17-17:** журнал попыток нельзя изменить или удалить.
- **A17-18:** зашифрованная подписка расшифровывается только правильным секретом.
- **A17-19:** push-payload не содержит ФИО, товар, количество или причину.
- **A17-20:** критичная панель показывает непрочитанные и недоставленные события.

## Полевые сценарии B21

- **A17-21:** Android/Samsung получает push при закрытом PWA.
- **A17-22:** iPhone получает push после установки PWA на домашний экран и разрешения.
- **A17-23:** отключение разрешения на телефоне не мешает читать ленту.
- **A17-24:** переход из push фиксирует прочтение и открывает нужный ролевой экран после входа.
- **A17-25:** тихие часы проверяются по московскому времени.
- **A17-26:** резервный организационный канал критичной тревоги зафиксирован регламентом.
