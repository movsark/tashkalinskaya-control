# B06.2. Контроль табеля, ручные отметки и корректировки

Статус: `реализовано и проверено локально; полевая приемка входит в B06.3`

B06.2 продолжает сквозной QR-сценарий B06.1 и добавляет рабочее место
ответственного, бухгалтера и администратора. Подтвержденные операции не
переписываются и не теряются: ручные события имеют отдельный признак, а
корректировки применяются как эффективная проекция поверх исходной истории.

## Что реализовано

- контрольный экран на выбранную дату и доступное подразделение;
- состояния `EXPECTED`, `ABSENT`, `OPEN`, `MISSING_EXIT`, `CLOSED`, `REVIEW`;
- плановое и фактическое время, подразделение, ручные признаки и сводные числа;
- ручной приход/уход текущим серверным временем с обязательной причиной;
- область ответственного только по своему цеху, область администратора — фабрика;
- защита ручной команды от повторной отправки через idempotency key;
- запрос бухгалтером или администратором на исправление прихода/ухода;
- подтверждение или отклонение корректировки только администратором после
  повторной WebAuthn-аутентификации;
- сохранение исходного `attendance.event` без изменения и отдельного снимка
  «до/после» в корректировке;
- применение утвержденного времени в эффективной проекции смены;
- автоматическое выявление незакрытой смены worker-процессом без фиктивного
  автоматического ухода;
- аудит и transactional outbox для ручной отметки, запроса, решения и
  `MISSING_EXIT`.
- создание администратором подразделений и дневных/ночных смен;
- назначение подразделения и смены из карточки сотрудника с немедленным
  обновлением личного QR;
- понятное состояние `Не настроено` вместо ложного сообщения об отсутствии сети,
  если сотруднику еще не назначена смена.

## Права

| Операция | Администратор | Бухгалтер | Руководитель | Ответственный цеха |
| --- | --- | --- | --- | --- |
| Контроль фабрики | да | да | да | нет |
| Контроль своего цеха | да | да | да | да |
| Ручная отметка | фабрика | нет | нет | только свой цех |
| Создать корректировку | да | да | нет | нет |
| Посмотреть корректировки | да | да | да | нет |
| Решить корректировку | да + step-up | нет | нет | нет |

Права проверяются API. Скрытие кнопки в интерфейсе не считается защитой.

## API

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/attendance/control` | контроль на дату/по подразделению |
| `GET` | `/api/v1/attendance/manual-reasons` | действующие причины исключений |
| `POST` | `/api/v1/attendance/manual` | ручной приход или уход |
| `GET` | `/api/v1/attendance/corrections` | очередь и история корректировок |
| `POST` | `/api/v1/attendance/corrections` | отправить запрос |
| `POST` | `/api/v1/attendance/corrections/:id/decision` | подтвердить или отклонить |
| `GET` | `/api/v1/attendance/setup` | подразделения и действующие смены |
| `POST` | `/api/v1/attendance/setup/departments` | создать подразделение |
| `POST` | `/api/v1/attendance/setup/shifts` | создать дневную или ночную смену |
| `GET/PUT` | `/api/v1/attendance/setup/employees/:id` | посмотреть или изменить назначение сотрудника |

## Инварианты

1. Ручная отметка использует только текущее время PostgreSQL.
2. Причина обязательна; `OTHER` без комментария отклоняется.
3. Повтор одной команды возвращает исходное событие и не создает новое.
4. Ответственный не может отметить сотрудника чужого цеха.
5. Бухгалтер не создает ручное событие от имени ответственного.
6. Корректировка не обновляет и не удаляет исходный event.
7. Только утвержденная корректировка меняет эффективное время в контроле.
8. Незакрытая смена помечается и вызывает outbox один раз, но не получает
   вымышленный уход.

## Проверки

- чистое применение миграций `0001`–`0005`;
- `npm run check`: форматирование, ESLint, TypeScript, тесты и production-сборка;
- 27 API-тестов с реальной PostgreSQL;
- интеграционные тесты ручной идемпотентности, области контроля и неизменности
  исходного события после утвержденной корректировки;
- фактический запуск worker: первый цикл пометил одну смену, последующие циклы
  дали ноль новых отметок, в outbox осталась одна запись.
