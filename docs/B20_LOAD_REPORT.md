## Обязательный staging-прогон до B21

Профиль `tests/load/factory-staging.example.json` моделирует 70 пользователей и
чтение табеля, производства, склада и контроля. Перед запуском:

1. загрузить обезличенный объём не меньше ожидаемого года;
2. включить staging-only read-доступ для синтетического администратора;
3. включить метрики двух app-узлов и трёх DB-узлов;
4. прогреть приложение пять минут;
5. выполнить профиль не менее трёх раз;
6. отдельно провести безопасные write-сценарии QR, производства и группы четырёх
   водителей на изолированной дате;
7. сохранить p50/p95/p99, ошибки, CPU, RAM, соединения БД, lock waits и размер очередей.

Команда read-профиля:

```bash
LOAD_BASE_URL=https://staging.example \
LOAD_BUSINESS_DATE=2030-01-15 \
LOAD_READ_TOKEN='<только локально>' \
node scripts/load-test.mjs --run tests/load/factory-staging.example.json
```

Исходный ключ хранится только в GitHub Environment, а Timeweb получает лишь его
SHA-256 отпечаток. Доступ работает только при `NODE_ENV=staging`, требует
активную фабричную роль администратора или руководителя и отклоняет любые
изменяющие HTTP-запросы до бизнес-логики. Секреты и полный ответ API в отчёт не
записываются.

После создания GitHub Environment `staging` тот же профиль запускается вручную
workflow `Staging gates`; порядок описан в [runbook B20.2](B20_2_STAGING_RUNBOOK.md).
