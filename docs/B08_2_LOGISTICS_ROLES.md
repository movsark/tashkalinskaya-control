# B08.2. Ролевые сценарии логистики

Статус: `реализовано`

B08.2 завершает рабочие сценарии графика до начала фактической погрузки. Все
проверки выполняются на обезличенных данных; реальные сотрудники, машины и
названия будут внесены владельцем на этапе B22.

В текущем интерфейсе B20 ручное создание дополнительного рейса администратором
скрыто по решению владельца. Маршрут API и неизменяемая история оставлены для
совместимости; повторное включение возможно только после отдельного решения.

## Что реализовано

- экран водителя `/logistics/today`, где видны только его опубликованные рейсы;
- планшетный экран склада `/logistics/warehouse` без административных черновиков;
- допуск рейса к погрузке только при открытой смене назначенного водителя за дату вывоза;
- сохранение проверенной смены, времени и сотрудника, выполнившего допуск;
- идемпотентный перевод рейса в `READY_FOR_LOADING` с аудитом и outbox-событием;
- второй и последующие рейсы территории только как `EXTRA_RUN` с причиной и комментарием;
- идемпотентное создание дополнительного рейса;
- технологический буфер 15 минут между рейсами одного водителя или машины;
- настройка буфера в БД для уточнения после пилота;
- запрет пересечения групп в одной физической зоне погрузки;
- адаптивные представления для телефона водителя и планшета склада;
- в «Моей погрузке» водитель без активного рейса выбирает фактическую территорию дня и нажимает `Приступил к рейсу`;
- там же водитель активного рейса видит две разные операции: `Передать рейс` освобождает территорию для сменщика без закрытия рабочего дня, а `Завершить рейс` сначала открывает единое меню возврата и порчи;
- для смены сотрудника первый передаёт рейс, после чего основной водитель или сменщик самостоятельно приступает к той же территории без подтверждения администратора; принятый ассортимент остаётся у территории;
- окончательное завершение выполняется только после проверки возврата и порчи, сохраняет историю дня и закрывает рейс;
- с наступлением нового московского дня экран открывает новую дату, а предыдущие даты остаются доступными через календарь;
- постоянная территория служит настройкой нормы и не считается фактическим выходом на рейс.

## Маршруты API

- `GET /api/v1/logistics/me/days/:date` — только роль `DRIVER` и только свои рейсы;
- `GET /api/v1/logistics/warehouse/days/:date` — роли `WAREHOUSE_KEEPER` и `ADMIN`;
- `POST /api/v1/logistics/runs/:id/ready` — проверка табеля и допуск;
- `POST /api/v1/logistics/runs/extra` — дополнительный рейс администратора.
- `POST /api/v1/logistics/me/route/activate` — начать фактический рейс территории;
- `POST /api/v1/logistics/me/route/:routeShiftId/end` — передать или окончательно завершить фактический рейс; тело явно содержит `HANDOVER` либо `COMPLETE`.

## Границы блока

Фактические строки погрузки, подтверждение водителем и двойное завершение входят
в B13. Календарное исключение среды для территории 9 связывается с календарем
B09. Доставка push-сообщений реализуется общим контуром B17; B08 уже публикует
надежные события в transactional outbox.

## Определение «готово»

- водитель не может получить чужой рейс;
- склад не видит черновики;
- без открытой смены допуск отклоняется понятным сообщением;
- повторный допуск не создает второй аудит или уведомление;
- дополнительный рейс не создается повторно при повторе команды;
- конфликт интервала, буфера или зоны блокируется сервером и БД;
- занятая территория не может быть отобрана вторым водителем; обычная замена всегда последовательная;
- передача рейса не выдаётся за окончательное завершение и не удаляет принятый ассортимент территории;
- окончательное завершение, возвраты и порча воспроизводятся по водителю, территории и дате;
- API и оба интерфейса проходят типизацию, тесты и production-сборку.
