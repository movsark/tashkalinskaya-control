# ADR-0001. Архитектура приложения

- Статус: принято
- Дата: 30.07.2026
- Связанные решения: A-02, A-03, A-04

## Решение

Система создается как модульный монолит в одном репозитории:

- Next.js и TypeScript для PWA;
- NestJS и REST/OpenAPI для API;
- PostgreSQL 18 как основная БД;
- отдельный worker для планирования, уведомлений и отчетов;
- транзакционный outbox и очередь на PostgreSQL;
- Redis и микросервисы не вводятся без измеренной необходимости.

Модули имеют явные прикладные границы и не изменяют таблицы других модулей напрямую.

## Причины

Для примерно 70 сотрудников главная задача — транзакционная целостность производства, склада и погрузки. Микросервисы увеличили бы стоимость эксплуатации и сложность восстановления без полезного эффекта для MVP.

## Последствия

- одна согласованная версия приложения;
- проще аудит, резервное копирование и приемочные тесты;
- отдельный сервис в будущем можно выделить только по реальной нагрузке или интеграционной необходимости.
