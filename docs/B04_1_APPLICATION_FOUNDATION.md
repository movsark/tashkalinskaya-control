# B04.1. Технический каркас приложения

Статус: реализован, проверен CI и объединён в `main`

## 1. Назначение

B04.1 закрывает разрыв между утверждённой архитектурой и функциональными
блоками. Это первая стадия, на которой в репозитории появляется промышленный
код приложения.

Каркас не реализует бизнес-функции фабрики. Он создаёт проверяемую основу для
B05 и следующих блоков:

- PWA-интерфейс;
- REST API;
- отдельный worker;
- общие контракты;
- PostgreSQL и миграции;
- локальное и контейнерное окружение;
- единый набор автоматических проверок.

## 2. Структура

```text
apps/
  web/       Next.js PWA
  api/       NestJS REST/OpenAPI
  worker/    фоновые задания и outbox
packages/
  contracts/ общие типы API
  database/  подключение PostgreSQL и миграции
deploy/
  docker/    отдельные образы web/API/worker
```

Репозиторий использует npm workspaces. Все процессы выпускаются одной версией,
но запускаются отдельно.

## 3. Зафиксированный стек

- Node.js 24;
- TypeScript 5.9;
- Next.js 16 и React 19;
- NestJS 11;
- PostgreSQL 18;
- Vitest;
- ESLint и Prettier;
- Docker Compose.

Актуальные версии фиксируются в `package-lock.json`. Обновление major-версии
проходит отдельной задачей и полным набором проверок.

## 4. Реализовано

### Web/PWA

- адаптивный стартовый экран;
- manifest и installable-режим;
- безопасная offline-страница;
- service worker не кеширует операционные API-команды;
- индикатор доступности API;
- базовые токены цветов, типографики и компонентов;
- production standalone-сборка.

### API

- версионированный префикс `/api/v1`;
- liveness `/api/v1/health/live`;
- readiness `/api/v1/health/ready`;
- OpenAPI `/api/docs`;
- CORS из конфигурации;
- security headers;
- correlation ID для запросов;
- структурные JSON-логи;
- корректное завершение процесса.

### Worker

- отдельный процесс;
- структурные события запуска, heartbeat и ошибки;
- проверка очереди outbox без преждевременной обработки бизнес-событий;
- безопасная остановка по сигналу;
- явное правило обязательности БД по окружению.

### PostgreSQL

- пул подключений с именем процесса;
- миграции под advisory lock;
- контроль хеша уже применённой миграции;
- повторный запуск миграции безопасен;
- начальные таблицы транзакционного outbox и аудита;
- PostgreSQL 18 в local/CI Compose.

## 5. Локальный запуск

Требуется Node.js 24.14 или новее в пределах major 24.

```bash
cp .env.example .env
npm ci
npm run dev
```

Без PostgreSQL web и API liveness работают, readiness показывает состояние
настройки БД. Worker не выполняет бизнес-операции.

При наличии Docker:

```bash
docker compose up --build
```

Адреса:

- web: `http://localhost:3000`;
- API: `http://localhost:4000/api/v1`;
- OpenAPI: `http://localhost:4000/api/docs`.

## 6. Проверки

Единая команда:

```bash
bash scripts/check-repository.sh
```

Она выполняет:

- защиту от чувствительных файлов;
- проверку локальных ссылок;
- Prettier;
- ESLint;
- TypeScript;
- модульные тесты;
- production-сборку всех процессов.

GitHub Actions дополнительно:

- поднимает PostgreSQL 18;
- дважды запускает миграции;
- проверяет production-зависимости через `npm audit`;
- собирает отдельные контейнеры web/API/worker.

## 7. Безопасность

- секреты не имеют значений по умолчанию для staging/production;
- `.env` запрещён к коммиту;
- local-пароль в `.env.example` не используется вне local/CI;
- приём критичных операций без серверного ответа в будущих модулях запрещён;
- production API требует доступную БД;
- найденные high/critical npm-уязвимости блокируют CI.

## 8. Ограничения первого среза

- ядро авторизации и сотрудников реализуется в B05.1/B05.2;
- реальные бизнес-таблицы создаются миграциями соответствующих блоков;
- push, S3 и отчёты подключаются последующими блоками;
- финальная дизайн-система создаётся отдельным UI-блоком;
- локальный Docker на текущем компьютере не установлен, поэтому сборку
  контейнеров проверяет GitHub Actions.

## 9. Определение «готово»

B04.1 готов, когда:

- `npm ci` воспроизводим из lockfile;
- web, API и worker собираются;
- API liveness отвечает;
- стартовый экран открывается на телефоне, планшете и офисном размере;
- миграция дважды проходит на чистом PostgreSQL 18;
- тесты, lint, типы, audit и production-сборка зелёные;
- три контейнерных образа собираются в CI;
- документация запуска соответствует фактическим командам;
- изменение объединено в `main`.
