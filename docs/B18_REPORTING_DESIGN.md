# B18. Центр контроля и отчетность

Статус решения: принят по ранее согласованному правилу «везде по рекомендации».

## Границы MVP

- центр контроля за выбранную дату;
- 12 отчетов: производство и чистый вывоз, движения, план/факт, брак,
  приемка, погрузка, возврат, порча, инвентаризация, нормы, табель и
  неподтвержденные операции;
- Excel как рабочая табличная форма и PDF как печатная форма A4;
- фоновые задания и реестр последних файлов;
- хранение готовых файлов 365 дней;
- руководитель и администратор видят все отчеты, бухгалтер — только табель;
- электронной подписи и штампа в MVP нет.

## Решения

1. API в одной транзакции читает данные и сохраняет нормализованный JSON-снимок.
   Worker строит файл только из снимка, поэтому повторная генерация не меняет итоги.
2. Снимок, файл, SHA-256, версия шаблона и параметры хранятся вместе в PostgreSQL.
   При масштабе фабрики это уменьшает число обязательных узлов и защищает от потери
   подтвержденного результата. Переезд файлов в S3 можно сделать без изменения API.
3. Срок диапазона ограничен 366 днями, число строк — 10 000. Ограничения защищают
   рабочую систему от случайной тяжелой выгрузки.
4. Табель содержит персональные данные и доступен только ADMIN, MANAGER и ACCOUNTANT.
   Остальные отчеты доступны ADMIN и MANAGER.
5. В каждом файле указаны период, время снимка, сформировавший сотрудник, версия
   шаблона, примененные фильтры и итоги.
6. PDF использует A4: книжная ориентация для узких таблиц, альбомная для широких.
7. Отчёт «Производство и вывоз» показывается таблицей прямо в приложении и
   выгружается в Excel. За период по каждому товару показываются подтверждённый
   выпуск, чистый вывоз и остаток обычного склада на конец периода. Чистый вывоз
   равен сумме текущих позиций погрузки, подтверждённых водителем, минус годный
   возврат, физически принятый складом и привязанный к той же дате вывоза. Для
   учёта позиции не требуется закрытие всей погрузки. Отчёт всегда суммирует всю фабрику:
   отдельного фильтра территории в нём нет. Отдельный склад порчи в остаток обычного
   склада не входит. Если водитель уже подтвердил позицию, но вся
   погрузка ещё не закрыта и складское движение не проведено, эта позиция сразу
   вычитается из показателя `На складе`; после проведения движения повторного вычитания нет.
8. Раздел открывается единым последовательным списком готовых отчётов. Параметры и
   результат появляются только после выбора конкретного отчёта. Пока практически
   реализован только «Производство и вывоз», поэтому в рабочем списке отображается
   только он; технический каталог остальных заготовок пользователю не показывается.

## Надежность

- worker захватывает задания через `FOR UPDATE SKIP LOCKED`;
- после сбоя RUNNING возвращается в очередь, максимум три попытки;
- READY возможен только при наличии файла и корректной SHA-256;
- входной снимок и параметры задания неизменяемы на уровне БД;
- создание и скачивание записываются в `audit.event`;
- просроченный файл переводится в EXPIRED, строка реестра не удаляется.

## Производительность

Оперативный экран выполняет только агрегирующие запросы с фильтром по дате. Создание
файла не выполняется в API-процессе. Для пилота контрольный предел — 10 000 строк в
одной выгрузке; после B21 он корректируется по фактическим замерам.
