# Сведение локального проекта и GitHub

Статус: требуется однократное выполнение перед началом функциональной разработки

## Исходное состояние

На 31 июля 2026 года:

- целевой приватный репозиторий: `movsark/tashkalinskaya-control`;
- локальная рабочая ветка содержит дорожную карту, решения B01–B03 и
  UX-прототип;
- GitHub `main` ранее наполнялся через веб-интерфейс;
- локальная и удаленная истории могли получить разные корневые commit;
- в текущей среде нет подтвержденной Git-аутентификации для безопасного fetch,
  push и настройки защиты ветки.

Это не влияет на проектные документы, но до разработки приложения должен быть
создан единый проверенный baseline.

## Безопасный порядок

1. Подключить GitHub App или `gh` к приватному репозиторию с минимальными
   необходимыми правами.
2. Выполнить `git fetch origin` и сохранить обе истории без reset/force push.
3. Сравнить полный список и контрольные суммы файлов в локальной ветке и
   `origin/main`.
4. Создать интеграционную ветку от актуального `origin/main`.
5. Перенести в нее принятые документы и прототип отдельным commit.
6. Убедиться, что исходное ТЗ сохранено без изменения, а секретов и рабочих
   данных нет.
7. Открыть pull request, дождаться CI и проверить diff владельцем.
8. Выполнить squash merge в `main`.
9. Включить правила защиты `main` из [CONTRIBUTING.md](../CONTRIBUTING.md).
10. Только после этого создавать ветку B05.

## Запрещено

- `git push --force` в `main`;
- `git reset --hard` для сведения историй;
- удаление одной истории до сравнения файлов;
- загрузка рабочего Excel, резервных копий, production-фото и секретов;
- утверждение, что репозиторий синхронизирован, пока fetch и CI не проверены.

## Критерий готовности

- GitHub `main` содержит все принятые документы и прототип;
- локальная ветка создается от того же commit;
- обязательный CI проходит;
- `main` защищена;
- владелец видит и принимает итоговый pull request.
