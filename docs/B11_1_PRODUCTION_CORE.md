# B11.1. Операционное ядро производства

Статус: `реализовано; физическая приёмка и полевая приемка закрываются в B12/B20`

## 1. Что вошло в срез

- атомарное и повторяемое создание заданий из актуального плана B09;
- дневное и ночное окно товара, включая утреннюю приёмку ночной продукции;
- настраиваемый основной цех и временная передача товара с решением администратора;
- назначение кондитеров только при активном аккаунте, роли нужного цеха и открытом приходе B06;
- командное задание с ровно одним ответственным;
- выпуск несколькими партиями с защитой от повтора запроса;
- отдельное согласование сверхплана и отзыв партии до начала проверки складом;
- неизменяемая фиксация частичного/нулевого выполнения с причиной;
- отдельный отчёт о браке и решение ответственного/администратора;
- ролевой экран для ответственного, кондитера, администратора и очередь для кладовщика;
- кабинет кондитера показывает общий «План производства на сегодня» по пяти
  группам и отдельно личные задания, назначенные ответственным цеха;
- аудит критичных команд и транзакционный outbox для будущих уведомлений B17.

## 2. Граница склада

Статус `AWAITING_WAREHOUSE` означает только заявление цеха. Он не создаёт
складский остаток. B12 добавит физическую приёмку, возврат на исправление и
неизменяемое движение принятого товара.

## 3. Технические артефакты

- миграция `0019_production_workflow.sql`;
- NestJS-модуль `production` и типизированные контракты;
- экран `/production`, адаптированный под телефон, планшет и офис;
- PostgreSQL-интеграционные тесты критической цепочки.

## 4. Что ещё не считается закрытым

- A11-15–A11-23 завершаются с физической приёмкой B12;
- фактическая загрузка фото в закрытое объектное хранилище входит в инфраструктурный срез;
- push-доставка событий входит в B17, но события уже записываются в outbox;
- полевой пиёмочный сценарий A11-44 входит в B20.

## 5. Проверка

Срез считается технически готовым после:

1. применения миграций на чистой PostgreSQL;
2. прохождения типизации, lint, сборки и тестов;
3. прохождения цепочки «план → задание → назначение → партия → очередь склада → невыполнение/брак»;
4. адаптивной проверки экрана на целевых ширинах.
