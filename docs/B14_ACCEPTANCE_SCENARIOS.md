# B14. Приёмочные сценарии

Статус: автоматизируемое ядро B14; полевые проверки камеры и нескольких устройств — B21.

## Автоматизированные сценарии

- **A14-01:** первый пересчёт за дату создаёт версию 1 и неизменяемый снимок всех активных товаров.
- **A14-02:** повтор команды открытия с тем же ключом возвращает тот же документ.
- **A14-03:** кладовщики сохраняют факт по отдельным строкам без потери данных.
- **A14-04:** устаревшая версия строки получает конфликт и не перезаписывает новый факт.
- **A14-05:** нельзя отправить документ с незаполненными строками.
- **A14-06:** повтор отправки не создаёт вторую фиксацию и вторые расхождения.
- **A14-07:** нулевая разница автоматически закрывает документ.
- **A14-08:** ненулевая разница создаёт открытое расхождение с правильным знаком и критичностью.
- **A14-09:** кладовщик не может закрыть ненулевое расхождение.
- **A14-10:** администратор закрывает расхождение объяснением без изменения остатка.
- **A14-11:** административная корректировка создаёт компенсирующее движение ровно один раз.
- **A14-12:** подтверждённые отправка и решение защищены от изменения и удаления.
- **A14-13:** поздний пересчёт создаёт новую версию, старая остаётся доступна.
- **A14-14:** движения после открытия не меняют снимок и показываются предупреждением.
- **A14-15:** план с подтверждённым пересчётом не содержит `INVENTORY_NOT_CONFIRMED`.
- **A14-16:** план без пересчёта использует системный свободный остаток и содержит тревогу.
- **A14-17:** руководитель имеет чтение, но не может выполнять команды.

## Полевые сценарии B21

- **A14-18:** сканирование реального штрихкода на Samsung, iPhone и iPad.
- **A14-19:** два кладовщика одновременно считают разные товары при нестабильной связи.
- **A14-20:** пересчёт после фактической погрузки укладывается в рабочее окно до 10:00.
- **A14-21:** администратор получает тревогу по просрочке и критическому расхождению.
