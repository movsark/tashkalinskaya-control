# B05. Закрытие административного контура доступа

Статус: реализовано; полевая приемка B05 остается воротами перед
пилотом B06.

## Результат

Администратор получил единую карточку доступа сотрудника:

- текущий статус аккаунта и трудоустройства;
- изменение статуса с обязательной причиной;
- изменение общезаводских ролей с обязательной причиной;
- история личных устройств, платформа и последняя активность;
- немедленный отзыв активного телефона;
- выдача recovery-кода для замены телефона;
- защита всех изменений свежим WebAuthn step-up.

## Границы ролей

До появления справочников B07–B08 экран редактирует только общезаводские
роли. Ранее назначенные роли цеха, территории, склада и магазина
показываются и сохраняются без изменения.

Сервер проверяет совместимость роли и области. Нельзя назначить кондитера или
ответственного цеха на всю фабрику, водителя — вне территории, продавца — вне
магазина.

## API

- `GET /api/v1/employees/:employeeId/access` — карточка и история устройств;
- `PATCH /api/v1/employees/:employeeId/status` — статус;
- `PUT /api/v1/employees/:employeeId/roles` — полная замена ролей;
- `POST /api/v1/employees/devices/:deviceId/revoke` — отзыв телефона;
- `POST /api/v1/employees/:employeeId/recovery` — код замены.

## Приемка

- просмотр карточки требует роль `ADMIN` области `FACTORY`;
- изменяющие операции требуют дополнительно CSRF и непросроченный step-up;
- причина обязательна;
- оптимистическая версия защищает от потери параллельных изменений;
- нельзя отключить последнего активного администратора;
- отзыв телефона немедленно отзывает его сессии;
- прямой API-запрос с ролью не в области `FACTORY` получает отказ.
