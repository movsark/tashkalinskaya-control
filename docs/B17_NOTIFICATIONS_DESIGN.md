# B17. Уведомления и эскалации

Статус: проектные решения приняты по правилу владельца «везде по рекомендации».

## Цель и границы

B17 превращает уже существующие транзакционные события `system.outbox_message` во
внутрисистемную ленту и Web Push. Ошибка push не отменяет и не меняет бизнес-операцию.

В MVP не входят SMS, Telegram, WhatsApp, электронная почта и автоматический звонок.
Резервный организационный канал для критичных тревог определяется перед пилотом B21.

## Решения N17-01–N17-18

1. Источник уведомления — подтверждённое outbox-событие, записанное в одной транзакции
   с бизнес-операцией.
2. Одна пара `outbox-событие + получатель` создаёт не более одной записи ленты.
3. Лента является основным каналом; Web Push — ускорителем и может быть недоступен.
4. Push содержит только безопасный общий текст без ФИО, количества, товара и причины.
5. Подробности открываются внутри приложения после входа и повторной проверки роли.
6. Каналы MVP: лента и стандартный Web Push с VAPID.
7. Открытие записи ленты считается подтверждением получения. Успешная доставка push
   подтверждением не считается.
8. Обычные сообщения соблюдают тихие часы 21:00–07:00 `Europe/Moscow`.
9. Важные и критичные сообщения обходят тихие часы.
10. Первая повторная доставка непрочитанной важной/критичной тревоги — через 15 минут.
11. Вторая эскалация критичной тревоги — через 30 минут; она видна в контрольной панели.
12. Получатели определяются каталогом событий, активными ролями и, где возможно,
    сотрудником из payload/операционного документа.
13. Отозванная или просроченная push-подписка отключается, но запись ленты сохраняется.
14. Временная ошибка push повторяется с увеличивающимся интервалом, максимум шесть попыток.
15. Подписка привязана к сотруднику и его единственному активному личному устройству.
16. Данные push-подписки шифруются AES-256-GCM отдельным production-секретом.
17. Журнал попыток доставки неизменяем; в нём нет содержимого подписки и push-текста.
18. Администратор и руководитель видят критичные непрочитанные сообщения и
    недоставленные push, но не могут отметить чужое уведомление прочитанным.

## Уровни

- `NORMAL` — рабочая информация, тихие часы, без эскалации;
- `HIGH` — важное действие, немедленный push и повтор через 15 минут;
- `CRITICAL` — риск остановки или расхождения, повторы через 15 и 30 минут.

Обязательные тревоги MVP:

- просроченный табель без ухода;
- публикация плана с неподтверждённой инвентаризацией и административная версия плана;
- складское или инвентаризационное расхождение;
- отклонение строки погрузки;
- запрос и решение по браку/списанию;
- критичная складская корректировка.

## Поток

```text
бизнес-транзакция → outbox → worker → лента получателя
                                      ├→ push сейчас/после тихих часов
                                      └→ повтор 15 мин / эскалация 30 мин
```

Worker блокирует сообщения через `FOR UPDATE SKIP LOCKED`, поэтому два экземпляра
приложения не создают дубли. Push-доставка обрабатывается отдельной очередью и не
удерживает транзакцию с бизнес-данными.

Обработчик B17 выбирает только события с активной политикой уведомления. Неизвестное
событие не помечается обработанным: оно остаётся доступным будущему отдельному
потребителю, в частности контуру интеграций B19.

## Промышленная конфигурация

- `PUSH_VAPID_PUBLIC_KEY` — публичный VAPID-ключ;
- `PUSH_VAPID_PRIVATE_KEY` — приватный VAPID-ключ только worker;
- `PUSH_VAPID_SUBJECT` — адрес владельца, например `mailto:...`;
- `PUSH_SUBSCRIPTION_ENCRYPTION_KEY` — отдельный секрет не короче 32 символов;
- все значения хранятся в секретах Timeweb и не попадают в Git.

## Критерии готовности

- повтор outbox не создаёт вторую запись ленты;
- неизвестное событие не поглощается и не создаёт push;
- отзыв подписки не влияет на бизнес-операцию;
- push-подписка не хранится открытым JSON;
- обычный push переносится за тихие часы;
- критичная запись доступна в ленте даже при всех неуспешных push;
- просроченная непрочитанная тревога получает эскалацию один раз на уровень;
- ссылка ведёт только на разрешённый ролевой экран;
- пользователь может отключить push и продолжить работать с лентой.
