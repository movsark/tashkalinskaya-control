# Инструкции Codex для проекта Ташкалинской фабрики

При любой работе в этом репозитории использовать skill `tashkalinskaya-control`.

Перед изменениями обязательно полностью прочитать:

1. `docs/PROJECT_STATE.md`;
2. `docs/UAT_PROGRESS.md`, если запрос относится к проверке приложения;
3. только относящиеся к задаче проектные документы из `docs/`.

Правила работы:

- продолжать с зафиксированного следующего действия, не повторять завершённые этапы без новой причины;
- писать владельцу фабрики простым русским языком;
- во время практической приёмки давать один короткий проверяемый шаг за раз;
- сначала проверять фактическое состояние кода, GitHub и стенда, затем делать вывод;
- сохранять чужие и незавершённые изменения в рабочей копии;
- не загружать реальные товары и сотрудников до отдельного решения владельца;
- не хранить в Git пароли, токены, одноразовые коды и значения секретных переменных;
- подтверждённые операции не удалять и не переписывать; исправления проводить компенсирующими операциями и аудитом;
- после изменения кода выполнять соразмерные тесты, работать через отдельную ветку и PR;
- после деплоя проверять `/api/v1/health/ready`, состояние базы и соответствие версии коммиту;
- перед завершением задачи обновлять `docs/PROJECT_STATE.md`, а при UAT — также `docs/UAT_PROGRESS.md`.

Если разговор и документы расходятся, уточнить факты по коду и внешним системам, затем обновить файлы состояния. Не переносить секреты из интерфейсов Timeweb или GitHub в ответы и документы.
